# Visual target and correction loop

Use this to reduce repeated creative misinterpretation. It does not guarantee first-pass quality or equal results across models.

## Set the target before generating

Use a user-accepted project example or supplied reference when available. Inspect it and record the specific qualities to carry forward: hierarchy, visual prominence, typography, density, section rhythm and explanatory interaction. A URL or the word “premium” alone is insufficient. If no reference exists, independently research and inspect relevant high-quality sites. Select a small set of benchmarks suited to the client, save screenshots and record their sources and specific craft qualities. Do not require Akhil to supply examples. Distinguish a quality standard for original design from a fidelity target for reproduction.

For a visually rich service landing page, consider a prominent relevant hero image, one consistent icon family, visual explanations of the service and purposeful motion. These are choices, not a universal template. A restrained brand, clone or explicit static brief can require different treatment. Never transplant another client's assets, identity, copy or claims.

## Review before extending

Review the generated hero against the external benchmarks at readable size before generating the rest of the direction. Similarity to the agent's own generated image does not establish design quality. Review the rendered hero at 1440 and 390 pixels before implementing the remaining sections. Ask:

- Does the design achieve comparable typographic, compositional and image quality to the external benchmarks, adapted to this brand? Name actual strengths and gaps; do not reward the presence of icons or animation alone.
- Does the composition meet the recorded visual target, beyond simply containing all the text?
- Does the primary image or diagram explain the subject or create intentional brand impact? Is its scale useful?
- Are headline, supporting copy and CTA clearly prioritised? Does mobile retain that hierarchy?
- Is density deliberate, rather than empty space on desktop or an undifferentiated text stream on mobile?

For the full page, check that adjacent sections perform different visual jobs. Icons and animation cannot compensate for weak composition. Preserve approved copy; use hierarchy and suitable disclosures rather than silently deleting content. Important claims, caveats and conversion information must remain easy to discover.

## Record evidence and correct

In the project's `QA/visual-review.md`, record the benchmark, screenshot paths or inspected viewport/section, specific observed weaknesses, corrections made and unresolved limitations. Include the rubric assessment. Keep functional test results separate. Do not invent defects to satisfy a quota, and do not treat a self-awarded score as independent validation.

If the visual target is missed, perform a focused correction pass, then inspect again. If the same underlying problem remains, change the composition rather than repeat cosmetic tweaks. Allow at most two focused correction rounds at a checkpoint under this default; respect any tighter user budget. If still unresolved, report the specific shortfall and attempted fixes without claiming completion or client readiness. Continue independent work where useful; request input only for a genuine missing decision or requirement.

## Learn without overclaiming

When the user accepts a revision, record the accepted version and the observable improvements in that project's brief. Distinguish user acceptance from the agent's own rating. Carry only relevant design principles into later projects. Record known model/settings without attributing improvement to reasoning effort when instructions and iteration also changed. A workflow text update is not proof of improved reliability; assess its effect on subsequent actual work.
